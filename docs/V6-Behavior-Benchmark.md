# V6 Behavior Benchmark

V6 starts with behavior measurement, not new mechanisms.

The benchmark protects two long-term Harness invariants:

1. Context Capability
2. Human Decision Authority

LOW Fast Path remains a constraint: these capabilities must not make ordinary deterministic work heavy.

## Benchmark Layers

### L1 Mechanical correctness

Unit and transaction tests verify schemas, validators, transactions, freshness classification, projections, and evidence records.

### L2 Deterministic acceptance fixtures

Fixtures verify observable governance behavior without depending on a live model.

Required fixture families:

- `context-coverage-fixture`
- `memory-evolution-fixture`
- `human-authority-fixture`
- `high-risk-governance-fixture`

The current candidate status is emitted separately from the frozen master baseline:

```bash
python scripts/acceptance/v6-behavior-baseline.py
python scripts/acceptance/v6-candidate-status.py
```

`v6-behavior-baseline.py` describes the fixed `main@f179c2e...` observation and must not be rewritten to pretend the baseline had V6 behavior. `v6-candidate-status.py` describes the current checkout and clearly distinguishes L2 success from live-runtime evidence that has not been run.

### L3 Runtime smoke

Real Codex and Claude fresh sessions validate:

- project entry loading;
- explicit Governor availability;
- SessionStart behavior;
- readonly Context Scout and Memory Scout startup;
- parent receipt of child results;
- Provider-valid attestation/evidence.

Synthetic transcript tests do not count as real runtime smoke.

Prepare a smoke project without running a model:

```bash
python scripts/acceptance/v6-runtime-smoke.py prepare <codex-project> --provider codex
python scripts/acceptance/v6-runtime-smoke.py prepare <claude-project> --provider claude
```

The prepare command returns `PREPARED_NOT_RUN`. It can never create a passing runtime result.

Before launching the fresh host session, set the project-local smoke evidence environment variable reported by `prepare`. Then start a genuinely fresh session from the prepared project and give it the generated `PROMPT.md`. Do not use resume or fork for this acceptance run.

After the session finishes:

```bash
python scripts/acceptance/v6-runtime-smoke.py verify <codex-project>
python scripts/acceptance/v6-runtime-smoke.py verify <claude-project>
```

A PASS requires all of the following evidence to agree:

- an opt-in SessionStart event generated by the real host session;
- the parent recorded the Task ID and secret canary from injected SessionStart context before repository reads;
- the Governor receipt hashes the actual generated Governor file;
- Context Scout and Memory Scout are both recorded as completed;
- each completed child request/record re-validates through the installed Provider attestation validator;
- the parent receipt points to the exact recorded child results;
- the governed work graph remains valid.

### L4 A/B benchmark

The primary C1 comparison uses:

- same parent model/configuration;
- same fixture repository snapshot;
- exactly the same task prompt bytes;
- fixed master baseline `f179c2ece4f5e428bfcd33d375c67f87a289e6cb`;
- current V6 candidate ref.

Prepare both sides:

```bash
python scripts/acceptance/v6-ab-benchmark.py prepare <ab-root> --model-label <exact-model-control>
```

The script materializes the two Harness refs, creates identical C1 fixture repositories, installs the corresponding Harness into each repository, hashes the fixture and prompt, and writes the oracle only outside the model projects.

Run two genuinely fresh Codex sessions with the same model/configuration, one in each prepared project, and give each its local `.v6-benchmark/PROMPT.md`.

Then score:

```bash
python scripts/acceptance/v6-ab-benchmark.py score <ab-root>
```

The scorer does not trust the Agent's `independent_exploration_completed` field. It accepts engineering exploration only when a recorded Locator/Context/Test/Framework Scout completion re-validates through that side's installed Provider attestation validator. It also rejects a comparison if the fixture or prompt changed after preparation.

The C1 score measures:

- required-context recall;
- context pollution;
- premature convergence;
- attested independent exploration;
- expected root-cause ownership.

The candidate must meet the C1 absolute target, avoid regression versus baseline, and show at least one strict behavioral improvement.

## Baseline Expectations

The frozen master baseline exposes known gaps:

- HIGH/CRITICAL exploration protected active Change execution but not every Investigation conclusion boundary;
- Learning and Knowledge supplied human-reviewed state but not version-aware Memory semantics;
- runtime tests proved Provider contracts but not the full real-session chain.

These are historical benchmark observations, not current candidate status.

## V6 Acceptance Scenarios

| ID | Scenario | Deterministic target | Final behavior target |
| --- | --- | --- | --- |
| C1 | Context coverage | fixture/scorer correctness | same-model A/B shows higher recall/lower pollution without premature convergence |
| C2 | Independent exploration | `inheritance=none`, parent hypothesis withheld | real child evidence remains independently sourced |
| C3 | Cross-session continuity | bounded Active Task Index + SessionStart projection | fresh session recovers the prior Task from injected context |
| C4 | Memory recall | only bounded relevant memory selected | parent receives only useful recovered history |
| C5 | Memory suppression | no match -> no Memory Scout | unrelated LOW work does not awaken history |
| C6 | Memory evolution | fresh/suspect/unknown Git semantics | stale history is not used as current fact |
| C7 | Open Thread | trigger-gated retrieval | unfinished work appears only when relevant |
| H1 | Human override | authoritative user decision propagated/frozen | Agent behavior never silently returns to its rejected recommendation |
| H2 | Material decision gate | unresolved forks block governed production progress | no production-critical semantic fork is silently chosen |
| H3 | No HITL overhead | LOW router creates no governed state | ordinary local work remains as lightweight as baseline |
| H4 | Human-curated memory | per-candidate decisions required | K/O/W candidates are not bulk promoted |
| H5 | Memory conflict | conflict -> historical lead; explicit supersede | no automatic merge/winner selection |
| G1 | Exploration gate | accepted/conclude/pivot block before Scout | governed final truth follows independent evidence |
| P1 | Long-term cost | startup payload independent of archive count | startup context remains bounded over project lifetime |
| P2 | Fast path cost | LOW work bypasses Memory subsystem | large history does not change ordinary LOW behavior |
| R1/R2 | Runtime smoke | protocol cannot self-pass | Codex and Claude fresh runtime evidence is real |

## Final-success interpretation

V6 is not considered fully accepted merely because L1/L2 are green.

The final success metrics remain:

- **Context Recall ↑** — determined by L4 C1 A/B;
- **Context Pollution ↓** — determined by L4 C1 A/B;
- **Human Authority = 100% for material decisions** — mechanically protected by H1/H2 and still requiring live behavior evidence that the Agent follows the user's choice;
- **Fast Path Overhead ≈ current master** — mechanically protected by H3/P2 and still subject to a final live LOW-task sanity case.

The final Codex acceptance should therefore include the C1 A/B run plus small live Human Override and LOW Fast Path cases. Those live cases are intentionally not executed by normal CI.
