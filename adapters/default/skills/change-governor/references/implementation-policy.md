# 实施策略

## 最小必要复杂度

不因“可以优化”而增加抽象、helper、状态、缓存、配置、日志、异常、fallback、兼容层或测试。

## 修改预算

HIGH/CRITICAL 实施前明确：允许文件/模块、类、状态、接口、职责、测试和非目标范围。超出预算必须停止并重新评估。

## helper

只有在提供稳定语义、消除真实重复或显著清晰主流程时新增。避免散落大量一两行、单次调用、语义弱的 helper。

## 错误策略

优先在 Creator/入口验证结构有效性。对象成功创建后信任其静态结构；运行期只处理真实动态错误。禁止 silent fallback。

## 实现子 Agent

只允许边界清晰、接口已批准、无共享状态和核心流程的切片。主 Agent 必须复核整体 Diff。
