# Sitter Grill

## Purpose

通过高价值追问消除会改变正式设计的关键歧义。它是 Governor 的辅助，不是独立开发流程。

## 先调查、后提问

能从代码、测试、知识库和用户已有回答中确定的事实不得再问用户。

只问必须由用户、业务或工程决策确定的问题，例如：

- 是否严格复现商业软件，还是满足工程误差即可；
- 哪个结果口径具有权威性；
- 是否要求历史兼容；
- trial/committed state、卸载和路径依赖的目标语义；
- 是否允许状态/职责/接口变化；
- 临时兼容是否允许及退出条件；
- 完成和验收标准。

## 提问方式

- 每轮聚焦同一决策主题；
- 给出已知事实和为何需要决策；
- 必要时给 2–3 个真实备选及影响，不机械凑方案；
- 发现用户回答与代码事实冲突时指出冲突；
- 不问文件名、变量名和 Agent 可自行判断的实现细节。

## 输出

生成或更新 `.agent-work/<task-id>/grill-decisions.md`：

- 已确认业务语义；
- 已确认数值语义；
- 架构权限；
- 兼容要求；
- 验收标准；
- 仍未确认项；
- 用户决策原意的简洁记录。

完成后交回 Governor，不进入 implementation。
